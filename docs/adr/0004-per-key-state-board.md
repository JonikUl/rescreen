# Per-key состояние для доски Status

**Status:** accepted

Доска состояния (тикет 10) хранит последний известный SnapshotResult по каждому SnapshotKey в отдельном файле `state.json`: filtered run сливает только затронутые ключи, остальные состояния сохраняются. Это не разворот ADR-0003: там отклонено слияние filtered run **в результат последнего Run'а** — `last-run.json` по-прежнему итог ровно одного Run'а, а Diff-файл по-прежнему единственный маркер неподтверждённости. `state.json` — отдельное представление для отдельной команды (`rescreen status`), на Report и Approve оно не влияет.

Причины: после частичных прогонов (`run home`) не видно общей картины — какие Page «красные» прямо сейчас; Report по решению тикета 06 остаётся итогом одного Run'а, поэтому доске нужен свой источник данных.

## Consequences

- `BaselineStorage` расширяется операциями `listSnapshotStates` и `pruneSnapshots`; `saveRunResult` сливает результаты в `state.json` по ключу; `approve` переводит состояние `diff` в `unchanged` с прежними датами, не трогая более свежие состояния других статусов.
- История состояний не ведётся: запись одна на ключ, заменяется целиком.
- Хранилища без `state.json` не мигрируются: до следующего Run'а такие ключи показываются как «нет данных».
- Сироты (ключи вне resolved-конфига) скрываются доской, но не удаляются; их уборка — явная команда `rescreen prune`.
