# Diff-файл как маркер неподтверждённого Diff'а

**Status:** accepted

Approve определяет, что можно подтвердить, по артефактам хранилища, а не по результату последнего Run'а. Инвариант: Diff-изображение по ключу лежит в хранилище тогда и только тогда, когда по этому ключу есть неподтверждённый Diff. Для поддержания инварианта Run удаляет Diff-файл, когда Snapshot снова совпал с Baseline'ом, а Approve удаляет его при подтверждении (текущий Snapshot → Baseline + удаление Diff'а + запись в Audit Log).

Причины: filtered `run <page...>` перезаписывает результат последнего прогона целиком, поэтому Approve, читающий этот результат, теряет Diff'ы остальных Page до полного перепрогона — а порядок «переснял одну Page до Approve другой» является штатным ежедневным сценарием. Альтернатива — мержить результаты filtered run в сохранённый результат (per-key recency) — отклонена: файл перестаёт быть результатом одного Run'а (сводка и дата в нём перестают что-либо значить), а спека фиксирует «храним только последний результат». Per-key Snapshot'ы и Diff-файлы в хранилище и так переживают filtered run — индексировать их отдельным файлом не нужно.

## Consequences

- `BaselineStorage` расширяется операцией листинга неподтверждённых Diff'ов и удаления Diff-файла; `approve` получает постусловие «Diff-файл удалён».
- `approve` не читает `last-run.json` и не читает конфиг: опечатка в имени Page — «нечего аппрувить» (exit 0), а не ошибка; Diff'ы Page, удалённых из конфига, аппрувятся вместе со всеми (их уборка — тикет 10, доска состояния).
- Report и `last-run.json` не затрагиваются: Report остаётся итогом одного Run'а.
- Реализация обязана удалять Diff-файл при статусе `unchanged` — до этого решения устаревшие Diff-файлы не удалялись никогда.
- Листинг восстанавливает ключи из имён файлов, поэтому селектор Element'а в имени файла кодируется hex, а не base64url: алфавит hex не содержит `_` и `x`, и суффикс `__<hex>` не может быть принят за разделитель viewport'а (`__<width>x<height>`) или содержать его — обратный разбор однозначен (жадный разбор page, slug может содержать `__`). Формат имён изменён до первой публикации пакета, миграция не требуется.
